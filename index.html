Click a BEFORE N marker, press Tab forward, and watch the tracker bar. For reverse, click AFTER N and press Shift+Tab. Try in each browser. Safari needs Full Keyboard Access on (System Settings → Keyboard → Keyboard navigation).

Scripted focus: with a BEFORE N marker focused (driven by the keypress so the modality stays keyboard): press f to call iframe.focus() — watch whether focus lands on the iframe element itself or descends to the first focusable inside (in Chrome it focuses just the iframe element). Press b to call focus() on the first button inside the iframe, testing whether a scripted focus on an inner element steals focus from the parent marker (button rows only; disabled under ?xorigin=1). Press m to postMessage the iframe asking it to focus its own first button — the cross-origin-safe version of b, so it works even under ?xorigin=1.

Focus rings: red outline = :focus matches (element is focused). Blue ring with white spacer = :focus-visible matches additionally (browser deems focus should be visible — keyboard-driven). So red only = mouse-focused, red + blue = keyboard-focused.

13. cross-origin focus-steal from an <input> · postMessage on Enter

Type in the input and press Enter — that posts the focus-first-button message to the iframe (same as the m key, but the focus source is an <input>). Per Mozilla bug 656026, Firefox blocks a cross-origin iframe from stealing focus away from an input element (the m-key test parked focus on a link, which was not blocked). Run with ?xorigin=1 to test the cross-origin case.
· Focus moves to the iframe (BUTTON 1 inside, or the iframe element cross-origin) → the steal succeeded.
· Focus stays in the input → the browser blocked the cross-origin focus steal.

How to run
  1. From this folder, serve over HTTP: python3 -m http.server 8000
  2. Open http://localhost:8000/index.html in each browser.
  3. For each test row: click BEFORE N, press Tab, note what the tracker shows. Then click AFTER N and press Shift+Tab.
  4. Scripted focus: with BEFORE N focused, press f to call iframe.focus() from JS (does focus land on the iframe or descend inside?), b to call focus() on the first button inside the iframe (does it steal focus from the marker? — button rows only, same-origin only), or m to postMessage the iframe to focus its own first button (cross-origin-safe; works under ?xorigin=1).
  5. Safari: enable Full Keyboard Access (System Settings → Keyboard → Keyboard navigation) or hold Option while pressing Tab.
  6. Cross-origin variant: append ?xorigin=1 to load the iframes from a second origin that serves the same files, so the parent can't read into them. Locally, localhost and 127.0.0.1 are different origins — open http://localhost:8000/index.html?xorigin=1 and the iframe srcs are rewritten to http://127.0.0.1:8000/.... When deployed, the swap is between models-resources.concord.org and models-resources.s3.amazonaws.com (the demo is published to both). The tracker's inner-element readout will then show "(cross-origin — cannot read inner)" instead of the inner activeElement, matching the AP scenario.
